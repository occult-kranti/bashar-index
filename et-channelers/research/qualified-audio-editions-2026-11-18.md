# Qualified YouTube audio editions

Some public recordings expose a downloadable combined MP4 while audio-only extraction is unavailable. The collection dashboard can account for an audio extract from that recording, with explicit uncertainty about the original audio track and spoken language. This capability reads saved metadata only. It starts no downloader, browser, Drive operation, transcription or media verification job. An empty qualified-edition journal contributes zero; supporting a receipt type does not establish that any real file has passed it.

The private acquisition worker must first obtain one complete selected format-18 response, extract its AAC stream without re-encoding, and preserve the ordered packet payloads, codec configuration, padding and timing. The recorded quality result must bind the exact source and derived file hashes and the existing verifier artifact. Whole-response Content-Length or full-extent 206, received/written byte counts, no redirect/retry and the observed body hash must agree. The archive contains `audio-extract.m4a` and canonical `provenance.json` under the creator's `AudioExtracts/<video>/<source-sha256>/` directory. Both require observed Drive MD5, size and distinct IDs. Local SHA-256 is never described as an observed remote hash.

`qualified_edition_receipts.py` checks that schema, the archived provenance bytes and the actual pair proofs. `ingestion_status.py` joins accepted records to the selected creator, video and tab; an unrelated creator or legacy/partial receipt does not count. Coverage uses one video-ID union, with native audio first, publisher audio second and additional qualified YouTube editions third. The channel CSV adds `qualified_youtube_only_audio`; the video CSV uses `youtube_track_unverified`. Existing dated snapshots that omit the new category continue to render as zero.

These receipts do not establish original-track identity, spoken language, speaker identity, recording/edit equivalence, translation status, full speech coverage or text accuracy. Native audio, native HTTP-success history, captions and ASR counts remain independent. A qualified audio transfer cannot reset a native refusal streak. Future analysis must use each edition's provenance and its own transcript binding rather than silently substituting it for another recording.

Tests use invented metadata and file fingerprints. They cover canonical provenance, detached file proofs, weaker quality claims, partial bodies, remote-pair mismatch, native/publisher overlap, creator joins, legacy rejection and the actual dashboard JavaScript's count, activity and CSV behavior. Actual acquisition and publication still require their separate owned execution and receipts.
