## Failure handling and crawling

A valid final worker result can exist without a progress file. The controller uses authoritative final diagnostics and preserves observed HTTP evidence before releasing a slot. Known, measured parent-enforced deadlines have separate censored records: no invented success, zero-request claim, streak reset or automatic retry. Fatal capture evidence cannot become a censored timeout or permit a sibling GO. Unknown failures, control-write failures, ownership failures and actual global source holds remain review conditions.

Recovery2's first retained exception was `PermissionError`; its operation stage was unknown, so a worker crash is not established. Sanitized fatal diagnostics now retain exception classes and bounded operation/stack context without raw URLs, credentials or private paths. Recovery3 then exposed a distinct pre-GO race: a sibling's bound 403 extended the adaptive pause after Popen, and an assertion falsely terminated the deferred child before GO. Recovery4 uses a bounded owned-child wait with guard rechecks under the dispatch lock and sleeping outside it, within the existing child GO deadline. This fixes control flow without retrying old targets, erasing HTTP history or treating a local deferral as provider refusal.

Recovery4 closed at **16:42 UTC** after 164 attempts: 140 paired/deleted archives, 23 held results and one missing worker terminal. All 140 local-complete audio files—**3,532,765,253 bytes**—were already uploaded with paired proofs and owned cleanup; no uploader is needed. Its final measured 92.844-second bootstrap deadline combined with a Win32 sharing violation during profile cleanup, so the strict clean-profile timeout exemption correctly refused it. This did not establish a new global provider refusal.

Source5 changes only that cleanup path: after proven owned-process closure and exact path/reparse checks, known Win32/33 sharing/lock errors may schedule delays totaling at most 15.5 seconds. Other errors stop immediately. Actual absence after an exception records clean truth, with the original failure retained. A blocking filesystem call itself is not canceled. Source retries, quality, worker count, HTTP history and strict closure rules stay unchanged. Admission projected **15.664 GB** from 9.297 GB actual managed bytes, 5.5 GB source growth, 0.8 GB other growth and journal reserve, below the 16 GB ceiling; no GPU or ASR action was admitted.

The crawler should retain distinct listing, attempted, available-audio and saved-text inventories. Incremental channel listings can discover new IDs after the frozen queue completes; metadata presence must never be mistaken for a downloaded-audio receipt. Preserve video/Shorts/live categories, source dates and stable IDs. Dashboard checkpoints can validate their generated JSON/CSV consistency without repeating the full Python suite when no code changes.

The experiment log should record input scope, exact versions, requests, bytes, elapsed phases, temporary-space peaks, validated completions and failure class. A new library or extension is promoted only after a complete file and its archive proof, not after a successful metadata request or short prefix.

## Panel rounds and measured priorities

The first round inspected primary project documentation, installed code and actual failure records. The second round independently reviewed the changed timeout and scheduling paths: 61 focused author tests and 14 independently selected changed-path tests passed. The third round checked live acceptance. The new cohort's first frame closed in **388.766 seconds**, archiving 16 recordings / 263,923,308 audio bytes. Three items lacked eligible formats; one measured parent deadline was isolated correctly. The controller continued into frame two automatically. Full transfer, strict audio quality and exact Drive proofs preceded coverage credit.

A source-free profile of the preceding closed 20-decision frame recorded 17 paired recordings / 285.44 MB over 371.514 seconds. Median intervals were 8.888 seconds from GO to selection, 7.351 seconds for media, 0.277 seconds for quality/metadata and 1.444 seconds for cleanup. The 25.266-second median from worker terminal to Drive proof includes queueing and is not isolated upload bandwidth. Browser/WPC and metadata time cannot be separated from those saved records. The process-plus-cleanup concurrency upper bound was 1.098 out of two, with 85.83 seconds having neither worker active; these are observations, not proof of one causal bottleneck.

Code inspection ruled out one proposed bottleneck: completed workers already reconcile their finalized folder as actual bytes and release the worst-case slot before publication. Live Source5 retains drain → refill → publish one ordering, with publication still synchronous on its manager. Earlier simulations changed 56 to 51 synthetic seconds for one heterogeneous case and stayed at 125 seconds when publisher-limited; they did not prove production gains. The new isolated scheduler uses a dedicated publisher and proves a fourth job can start while the first publication is deliberately blocked, while retaining two source futures and bounded pending output. It still needs a separately reviewed runtime adapter.

The later saved 140-decision profile measured process-plus-cleanup concurrency at most 0.973 of two, about 1,130 seconds without either interval active and about 962 seconds overlapping ready files. Five intentional 30-second pauses and unlogged publication/copy boundaries prevent a causal Drive-bottleneck claim. Instrument those boundaries and forced scans in the next experiment. Metadata-first admission also remains a future integration: four static slots need 8.96 GB against 5.5 GB, whereas exact-size grants may fit more eligible work. Unknown sizes retain full 2 GB grants, underestimated extra writes fail before disk, and retained/publisher files stay charged. Cross-item browser reuse needs fresh binding and owned-session evidence. Quality checks took too little measured time to justify relaxing them. Progressive MP4/AAC remains a separately scoped coverage fallback with complete-source and packet-equivalence proofs.

Normal official-feed CDN routing provided real parallel acquisitions: the latest two Steve Nobel MP3 editions passed packet checks, paired Drive verification and owned cleanup while native work continued. This brings that publisher lane to seven editions. Distinctive titles, dates and durations qualify their associations; exact YouTube edit/spoken-content identity remains unverified. Active source executables stay frozen while further experiments are prepared separately.
