# Bounded official-publisher caption batch, November 18

`pipeline/publisher_caption_batch.py` is a separate text-only component. It uses `youtube_captions.normalize_caption(raw, 'vtt')`, with explicit injected transport, fresh admission, private storage and verified publication callbacks. It does not instantiate the audio-first `MirrorBatch`, call YouTube/WPC, download audio, launch a browser, mint tokens, run ASR or write the native caption journal. There is no default network or Drive implementation and no executable CLI.

The prepared private scope has exactly three already audio-verified Erin publisher associations. Each saved official RSS item contains an explicit matching YouTube reference and advertises its static Buzzsprout VTT pointer. The podcast durations differ from the approximate queue durations by one second. These are exact references, not proof of identical edits or caption alignment. The feed declares US English; track language, manual versus automatic origin, translation status and complete spoken coverage remain unverified. Cached episode descriptions are summaries, not substitutes for full captions.

One separately authorized metadata-only robots GET returned HTTP 200 with 36 bytes, no redirect/retry, in about 0.203 seconds. Its exact raw SHA256 is `865dbdbd53dee048bdf5fc6fcb6e7d7534e42603371249bfd750007b6cee886b`; rules allow the three exact static paths for the fixed publisher-caption-reader user agent. That proves robots permission, not VTT endpoint acceptance. No VTT request or Drive call is part of preparation. Earlier control-review observations remain immutable; the new robots proof is a separate dated sidecar.

## Admission and transport

The private disabled grant binds the immutable candidate tuple, source/authority/feed/native-receipt evidence, code, robots body, owner, lease and **10,000,000-byte reservation**. An enabled Root grant and a fresh matching active lease/reservation are required before any fetch. The injected guard must actually inspect current publisher root stops, host/provider/endpoint holds, exact refused requests, Drive cooldown, robots freshness and storage. It must include all active growth in the 16 GB managed / 20 GB owner allowance with 2 GB unused, plus physical spare. The independent YouTube provider's native worker, ledger and controls are unchanged.

`native_audio_receipt_sha256` pins the exact canonical-record **file bytes**, including its JSON formatting and final newline. A digest of the parsed record serialized again is a different claim. The first private admission stopped before runtime creation or any fetch because its preparation used that second digest. A separate corrected scope preserves the original alias and spent admission, binds the raw file digest, and still requires the mature paired-receipt check. Private regressions exercise the real guard: raw pins pass, canonical-JSON aliases and formatting-only changes fail, and a matching file digest cannot substitute for a complete audio-plus-metadata receipt.

The old Buzzsprout audio refusal and its immutable scope binding remain preserved. Its elapsed deadline is not caption permission or a new endpoint acceptance proof. Missing current host/robots evidence cannot become an allow decision. The existing shared publisher_runtime/lanes helpers were not present in this checkout; no alternate helper or audio-first execution was assumed. `fetch_publisher_text.Robots` can fetch implicitly, and the older mirror transport does not supply this whole bounded contract, so the component instead requires explicit decision/transport proofs.

After review, the proposed batch permits **three initial VTT GETs, one per exact pointer**, serially with one I/O owner. It reuses the accepted cached robots body, so no further robots GET is needed unless separately granted. Each response is at most **1,000,000 bytes** with a finite 30-second total request deadline, identity encoding, zero redirects, zero retries, no cookies, credentials, browser identity changes or proxies. No alternate format, filename suffix, host or audio route is tried. The real transport must enforce the deadline during connect/read and preserve truthful timeout/partial observations; a post-return clock check alone cannot cancel a blocked system call.

A durable request-start event precedes the sole transport invocation. The callback must return the exact final URL, one wire GET, no followed redirects, actual status/length/body completion and completion time. A complete bounded exact-URL 404/410 without Retry-After, protection or a redirect is recorded as unavailable and the other distinct pointers continue. It is never retried. HTTP 401/403/429, protection or Retry-After stops all remaining caption requests. A scope-bound host/caption hold is persisted before returning; it retains existing history and never shortens a longer hold. Invalid Retry-After requires review. Truncation, unknown 5xx, control and parsing failures still hold the batch. These events do not create or clear a native YouTube failure. An ordinary redirect is an unaccepted routing observation, not silently relabeled as a quota refusal.

## Private artifacts and proof order

The raw body is retained before parsing. A valid VTT becomes a deterministic ZIP with `raw.vtt`, normalized `segments.json`, cue-rendered `transcript.txt`, qualified provenance and a member manifest. Normalization preserves cue order, timing and repetitions. It does not infer missing speech, align the publisher edition to native audio or establish transcription accuracy. Normalized output, archive, sidecar and one-item workspace are hard-bounded to fit the 10 MB reservation. An amplification, parse or storage failure stops with raw evidence retained.

One publisher archives the ZIP plus a separate provenance JSON under `PublisherSourceText`, using the existing mature exact-file copy/stat helpers in a private adapter. Each receipt explicitly separates its **local** bytes/MD5/SHA256 from **observed remote** bytes/MD5/Drive ID/path. Remote size and MD5 must match the local artifact; IDs must be distinct and paths exact. A local SHA256 is never presented as a remotely observed SHA256. A durable **publisher-source text** receipt precedes owned raw/archive/temp cleanup. Publication, receipt-write or cleanup failure preserves truthful retained state; a cleanup failure after a durable verified receipt does not revoke the actual archive proof. No local-complete or status string is treated as verification.

The separate publisher-text journal is proposed as `sync/publisher_caption_text_manifest.jsonl`, under an independent publisher-text lock. It must not acquire the native collector lock held by a frame or append to native audio/caption/ASR journals. Publisher source kind, exact-reference basis, feed-declared language, unknown origin/translation, unreviewed alignment and edit equivalence remain explicit. Native audio/full-ASR/native-caption counters do not increase. Integrating these qualified texts into a public coverage reader or later ASR exclusion requires its own receipt-schema review.

## Required adapter before execution

The prepared private runner implements these callbacks for Root review: fresh exact-file grant/lease/resource and saved-native-receipt checks; no-redirect transport; fsynced one-shot events; retained raw storage within 10 MB; exact two-object Rclone copy/stat verification; independently locked publisher-scope refusal merging; and proof-before-owned-cleanup. Each HTTP request runs in a dedicated owned fetch child. It cannot contact the host until the parent attaches its Windows Job and publishes FETCH_GO. A separate parent watchdog terminates that exact Job at the request deadline, covering DNS and read trickle; owned closure verification has its own bounded grace and remains separately recorded. No unowned process is terminated. The guard runs again after waiting and before dispatch. No plaintext credential, signed URL or response body is printed. This runner still requires independent review and an enabled Root grant; its existence is not execution permission.

Focused fixtures forbid network/process launch and cover the three-item serial path, qualified labels, real robots disallow/expiry, inactive/wrong grant/resource controls, storage/response/deadline limits, first-refusal stop and Retry-After, ordinary unavailability, no alternate-route retry, accepted-raw retention, explicit local SHA versus observed remote MD5, exact paired proofs and durable receipt ordering. Private adapter fixtures inject the HTTP response, owned Job/process and Drive client, including a watchdog acting while parent metadata I/O is blocked. They do not prove endpoint acceptance. The original private scope remains disabled until Root reviews the complete runner and issues its new grant.
