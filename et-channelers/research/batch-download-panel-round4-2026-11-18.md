# Download optimization panel, round 4 — November 18

The priority remains newest-20 audio acquisition, metadata, available English text and verified Drive publication. ASR is paused. This panel assigns the download owner to live execution/reconciliation, the admission engineer to capacity and scheduling, the transport engineer to alternate sources and independent review, and the lead to integration, evidence and release.

## Measured constraints and current recovery

The first seven closed recovery4 frames contain 140 decisions and 120 paired archives / 3,088,519,721 audio bytes over 3,684.8 seconds. Combined browser/WPC/metadata time from GO to selection has a 9.77-second median; selected-media time 9.35 seconds; quality/metadata 0.311 seconds; cleanup 1.569 seconds. Terminal-to-verified lag is 32.48 seconds, including queue and publication. Pure Drive copy/stat and capacity-scan timing were not recorded.

Process-plus-cleanup concurrency averaged at most 0.973 of two source workers. There were 1,129.8 seconds with neither active; 962.2 seconds overlapped completed files awaiting receipts. Five bound media refusals also impose deliberate 30-second dispatch pauses. These overlaps do not establish one causal bottleneck. The observed media-stage aggregate service was 1.870 MB/s per active worker, against a configured 2 MiB/s ceiling; whole-run archived throughput was 0.838 MB/s.

The final recovery4 audit accounts for all 164 attempts: 140 paired/deleted archives, 23 held and one missing worker terminal. All owned jobs closed; no local-complete pair needs an uploader. The last failure combined a measured 92.844-second bootstrap deadline with Windows sharing violation 32 during profile cleanup. The full 507-outcome history has consecutive-refusal tail zero and no global circuit. Original attempts, the retained profile and the original failed audit remain preserved. The separately admitted 453-target / 23-frame recovery5 continuation launched at 17:06:24 UTC with two source workers and one publisher.

The minimal cleanup revision extends filesystem-only retries for Win32 sharing/lock errors 32/33 to a bounded 15.5-second scheduling window after owned process closure and exact path checks. Permanent errors retain their immediate hold. Actual absence is rechecked after a failed removal; cleanup success is never invented. A blocking filesystem call itself cannot be safely canceled, so 15.5 seconds bounds retry scheduling rather than a hard kernel-call duration.

Live recovery5 acceptance exercised this exact failure class: a measured bootstrap timeout was followed by three sharing-lock failures, then a successful fourth cleanup attempt after 3.609 seconds (3.5 seconds scheduled sleep). The strict parent-censored descriptor validated actual closure and cleanup while retaining unknown source access, no success credit and no HTTP streak reset. The first frame closed at 17:15:01 UTC with 13 verified pairs / 336,444,674 audio bytes and seven held decisions, then advanced automatically. This proves the cleanup recovery path; it does not isolate a throughput gain or complete every held item.

## Options reviewed and decisions

|---|---|
| Scheduler / concurrent publication | The current manager calls publication synchronously. Finished source workers cannot be refilled during that call. An isolated bounded manager with two source workers and one independent publisher is now implemented and independently tested; its controlled fixture refills a fourth job while publication remains blocked. Live integration must measure refill and publication intervals. Byte admission, canonical receipts and completed-file backpressure remain prerequisites. |
| Metadata-first admission | Four static 2 GB + 240 MB slots require 8.96 GB, above the 5.5 GB spool. The sample's largest known selected file is 145.14 MB. Reserve 240 MB for bootstrap, upgrade to the selected enforced size before MediaGO, and retain the full 2 GB allowance when unknown. Four children with two unknown media/two bootstrap jobs plus one publisher envelope require 5.20 GB before inactive files. See the [component contract](native-admission-budget-prototype-2026-11-18.md). |
| Browser reuse / WPC | Installed WPC 1.1.2 retains its browser within a provider instance; the current per-video process ends that instance. A future owned worker session could amortize startup, while minting a correctly bound token for every new video. Browser/process ownership, per-item deadlines and observed RAM need separate acceptance. [Provider code](https://github.com/coletdjnz/yt-dlp-getpot-wpc/blob/main/yt_dlp_plugins/extractor/getpot_wpc.py), [binding guide](https://github.com/yt-dlp/yt-dlp/wiki/PO-Token-Guide). |

| yt-dlp fragment concurrency | `-N` applies to DASH/HLS fragments. The current selected sources are plain HTTPS files, so it does not add video-level concurrency here. [Download options](https://github.com/yt-dlp/yt-dlp#download-options). |
| aria2 / HTTP ranges | Range parallelism is a candidate for larger eligible objects. It needs a bound exact source, correct 206/Content-Range coverage and complete nonoverlapping reconstruction. | Progressive MP4 → AAC | The existing exact-two pilot can recover audio when saved metadata lists an eligible combined format but no eligible audio-only format. [FFmpeg streamcopy](https://ffmpeg.org/ffmpeg.html#Streamcopy), [ffprobe](https://ffmpeg.org/ffprobe.html). |
| YouTube.js / googlevideo SABR | These projects provide alternative extraction/streaming implementations. [YouTube.js](https://github.com/LuanRT/YouTube.js), [googlevideo](https://github.com/LuanRT/googlevideo). |
| pytubefix / other extractors | A second extractor can compare an eligible format inventory, but successful metadata extraction alone does not prove complete acquisition. Keep source identity, original audio selection and HTTP observations explicit. [Primary documentation](https://github.com/JuanBindez/pytubefix/blob/main/docs/index.rst). |
| Browser extensions / playback | Browser inspection can establish available formats and context. Tab capture consumes playback time and creates another artifact. It remains an inspection/exception path rather than the bulk downloader. [Chrome tab capture](https://developer.chrome.com/docs/extensions/reference/api/tabCapture). |

| Upload batching / persistent uploader | Native publication already batches audio+metadata with two transfers, then obtains exact batched remote proofs. Increasing batch size is not a missing fix. Instrument copy/stat, scan and queue time before selecting a persistent uploader. Larger Drive chunks consume one buffer per transfer. [Rclone performance](https://rclone.org/docs/#performance), [Drive chunk settings](https://rclone.org/drive/#drive-chunk-size). |

Reuse saved metadata for decisions and avoid refetching already-indexed pages. Keep Shorts, ordinary videos and live categories explicit; first-pass plans stay frozen while discovery evolves. [yt-dlp options](https://github.com/yt-dlp/yt-dlp#general-options). |

## Components and promotion evidence

`pipeline/native_bulk/admission_budget.py` models exact ownership, immutable selection, atomic size upgrades, on-write limits, retained-file reconciliation and a single publisher. `selection_gate.py` binds the durable request/MediaGO exchange to the lease, plan, attempt, worker, settings and nonce. The gate checks the real budget permit's job, metadata and byte ceiling before publishing permission. Its atomic no-overwrite control publication exposes only a fully flushed file; housekeeping failure after publication preserves a truthful committed acknowledgement.

The [scheduler prototype](native-parallel-scheduler-prototype-2026-11-18.md) separates publication from the manager loop. These components require a new executor integration and exact admission before source use; their fixtures prove contracts rather than production speedup. The portable source package mirrors the separately reviewed recovery5 cleanup implementation; the new admission, gate and scheduler components remain isolated from that running executor.

Before a concurrency trial, record same-size frame service, verified pairs/bytes, Source requests and failures, source-active intervals, selected-size waits, ready bytes, publication start/copy/stat/finish, forced-scan duration, retained bytes, process RAM and physical spare. Require complete owned closure, unchanged HTTP/protection rules and exact paired Drive proof. Begin with four total children/two media slots; consider more media only after the measured result and capacity evidence support it. Changing a worker-count setting alone is insufficient.

Automatic approval review rejected creation of a new public progressive verifier module with the stated reason “blocked by policy.” That creation is stopped. Review and preparation use the existing separately owned verifier and its existing packet; this report does not claim that the blocked module was built.
